# MCP Debugger

> Postman-style console for **MCP (Model Context Protocol)** servers, right inside your IDE.

指向一个 MCP 服务端（本地 `stdio` 命令，或远端 `HTTP` / `SSE` 地址），插件自动完成 MCP 握手、
拉取**全部工具**并列出；点开任意工具，参数区已经按它的 JSON Schema 预填好一份模板，改完调用即可。
不用写客户端代码，不用重启 IDE，也不用猜参数长什么样。

适用于 **PyCharm / IntelliJ IDEA / WebStorm / GoLand** 等所有 JetBrains IDE。

---

## 功能

| 能力 | 说明 |
| --- | --- |
| **三种传输** | `stdio`（子进程）、**Streamable HTTP**、旧版 **HTTP+SSE**。会话 id、协议版本协商、能力声明全部自动处理 |
| **自动获取工具** | 工具列表来自 `tools/list`（含游标翻页）；资源、资源模板、提示词一并列出。服务端发 `tools/list_changed` 通知时自动刷新 |
| **参数模板自动预填** | 按工具的 JSON Schema 生成参数 JSON：**声明的参数一个不少**，值取 `default`、枚举首项或按类型的空值（`""` / `0` / `false` / `[]` / `{}`）；`$ref` 与 `allOf` 会被展开，嵌套对象递归展开 |
| **定义随时可查** | 旁边一个「定义」页签就是工具的原始 JSON（含 `annotations`、`outputSchema`），参数的类型、必填、说明、默认值都在里面 |
| **历史卡片一键重发** | 每次调用都记成一张卡片——**状态、时刻、耗时**一行看完，入参与响应在悬停气泡里；卡片上那个「重新调用」直接把这一份再发一次（成功、服务端报错、本地失败都记） |
| **结果原样呈现** | 调用结果直接摊成一份 JSON（编辑器级高亮、可滚动、可复制），不再做二次渲染；调用耗时显示在状态旁边 |
| **报文级日志** | 请求、响应、通知、子进程 stderr 全部按方向与时间落到控制台 |
| **请求头分两级** | 服务器级（入口在工具栏，带在**所有**请求上，含握手与 SSE 建连）与工具级（工具详情的页签，只作用于该工具的 `tools/call`，同名键覆盖服务器级）；两级都改成表单填写，键可下拉选常用头 |
| **断连不丢目录** | 长连接断开后工具列表照常显示（只标"已断开"，条目暂时不能调用），后台按 1s→2s→4s…30s 退避自动重连 |
| **导入现成配置** | 粘贴 / 导入 Claude Desktop、Cursor、VS Code 的 `mcpServers` JSON；也会自动扫描工程内的 MCP 配置文件 |
| **中英双语界面** | 全部文案中英成对，默认**严格跟随 IDE 语言**；工具栏一键切换，就地重贴文字、不重建面板（展开状态、滚动位置、已敲的内容都保留） |
| **自动定位当前工程** | 配置按「全局」与「本工程」两档存放，工程级配置可随仓库共享 |

## 安装

### 从发行包安装（推荐）

```bash
./gradlew buildPlugin
# 产物： build/distributions/mcp-debug-idea-plugin-<版本>.zip（当前 1.0.5）
```

Windows 下也可直接双击 `package.bat`，它等价于上面这一步并打印产物路径。

然后在 IDE 里：**Settings → Plugins → ⚙ → Install Plugin from Disk…** 选择该 zip，重启 IDE。

### 从源码运行（开发调试）

用 IDEA 打开本工程，等待 Gradle 同步完成，执行：

```bash
./gradlew runIde
```

会拉起一个装了本插件的沙箱 IDE。

> **注意**：本工程的 Gradle Wrapper jar 未随仓库提交，若 `./gradlew` 报
> `找不到主类 GradleWrapperMain`，请改用本机 gradle 发行版，例如：
> ```bash
> "$HOME/.gradle/wrapper/dists/gradle-8.13-bin/<hash>/gradle-8.13/bin/gradle" buildPlugin
> ```

## 快速上手

1. 重启后在 IDE 右侧边栏找到 **MCP Debugger** 工具窗口。
2. 点工具栏的 **➕** 新建一个服务端配置，或者点 **📋 粘贴导入** 把现成的 `mcpServers` JSON 贴进去。
3. 选好服务端，点 **Connect**。状态点变绿、工具树开始填充，就说明握手成功了。
4. 左侧树里选中一个工具 → 右侧参数区已经按它的定义带出了参数 JSON → 改好点 **调用**（或按 `Ctrl+Enter`）。
   调过的入参会自动留在旁边的 **「历史」** 页签里，下次点一下就能填回来。
5. 调用结果以 JSON 直接显示在下方（可滚动，点状态条右侧的 **复制** 拿走同一份内容），**Console** 里是报文流水。

### 三种传输怎么填

**stdio**（本地子进程）

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:/data"],
      "env": { "LOG_LEVEL": "debug" }
    }
  }
}
```

也支持 `uvx` / `docker` / 任意可执行文件。插件会以 JSON-RPC 逐行读写子进程的 stdout/stdin，
stderr 原样转进 Console 面板。

**Streamable HTTP**

```json
{
  "mcpServers": {
    "remote": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer xxx" }
    }
  }
}
```

会话 id 从响应头 `Mcp-Session-Id` 自动拾取并回带。

**旧版 HTTP + SSE**

```json
{
  "mcpServers": {
    "legacy": {
      "type": "sse",
      "url": "https://example.com/sse"
    }
  }
}
```

先 GET 建 SSE 长连接，从 `endpoint` 事件拿到回传地址，之后 POST 走该地址，响应从 SSE 流里读。

## 界面布局

工具栏刻意分成两行，为的是适配右侧边栏（PyCharm / IDEA 里这个窗口默认停靠在右边，
宽度通常只有 300~400px）：下拉框独占一行；第二行左边是 5 个图标按钮 + 状态文字，
最右端是**语言切换按钮**（中文界面显示 `EN`、英文界面显示 `中`，点一下即时切换），
编辑 / 删除 / 导入导出收进「管理」。

```
┌──────────────────────────────────────────────────────────────────────┐
│ [ 服务端 ▾ ................. ] [ 请求头 · 1 ]                        │  工具栏
│ ➕ ↻ ✏️ ⚙️ ▤    ● 已连接 · 12 工具                                EN │
├───────────────────────────┬──────────────────────────────────────────┤
│ 目录树                     │  详情 / 调用区                            │
│  ├ 工具 (12)               │  ┌────────────────────────────────────┐  │
│  │   ├ add                 │  │ 名称 · 描述 · 来源                  │  │
│  │   ├ echo                │  ├────────────────────────────────────┤  │
│  │   └ …                   │  │ [ 调用 ] ⟲ ⚡   以 3 个参数调用      │  │
│  ├ 资源 (3)                │  ├────────────────────────────────────┤  │
│  ├ 资源模板 (1)            │  │ JSON │ 请求头 (1) │ 定义 │ 历史 (3)│  │
│                            │  │ ┌────────────────────────────────┐ │  │
│                            │  │ │  {                              │ │  │
│                            │  │ │    "a": 0,                      │ │  │
│                            │  │ │    "b": 0                       │ │  │
│                            │  │ │  }                              │ │  │
│                            │  │ └────────────────────────────────┘ │  │
│                            │  ├────────────────────────────────────┤  │
│                            │  │ ● 调用成功 · 12 ms           [复制] │  │
│                            │  │ {                                  │  │
│                            │  │   "content": [ … ]                 │  │
│                            │  └────────────────────────────────────┘  │
├───────────────────────────┴──────────────────────────────────────────┤
│ Console  10:42:01.113  ← {"jsonrpc":"2.0","id":3,"method":"tools/call"… │
│          10:42:01.115  → {"jsonrpc":"2.0","id":3,"result":{"content"… │
└──────────────────────────────────────────────────────────────────────┘
```

**请求头分两级：服务器级与工具级。** MCP 里 `tools/call` 就是一次普通的 JSON-RPC 请求，发到同一个
端点上，所以"给这一次调用换一组头"在协议上完全成立；真正需要分清的是哪一级管什么：

| 级别 | 带在哪些请求上 | 入口 |
| --- | --- | --- |
| **服务器级** | 全部：`initialize` 握手、SSE 建连的 GET、`tools/list`、所有 `tools/call` | 工具栏第一行、紧挨服务端下拉框的 **`请求头 · N`** 按钮 |
| **工具级** | 只在 `tools/call`，且工具名命中时 | 工具详情的 **「请求头」页签** |

**合并规则：逐键合并，同名以工具级为准。**

**服务器级**点开后是一个弹窗，一行一个头：键可以从下拉里挑常用项，选中 `Authorization` 会自动带上
`Bearer `。

```
│ [ 服务端 ▾ ................. ] [ 请求头 · 1 ]                        │  工具栏
```

按钮上的 `N` 就是当前条数，不点开也能一眼看出 token 到底在不在。弹窗里改完要点「确定」才写入——
服务器级这一层通常就一个 token，边改边写意味着手一滑就把能连上的那个值盖掉了。弹窗里还带一个
**测试连接**：它拿表单里这份还没保存的头去试一次握手，所以填完 token 不用先确定、也不用回主面板点连接。

入口放在工具栏而不是详情区里，是因为**它不能受连接状态影响**：带鉴权的新服务器恰恰是在"还没连上、
树是空的"时候最需要填 token 的，入口要是住在详情区就会被空态卡片挡住，首次配置直接死锁。
stdio 服务器没有 HTTP 头，这个按钮置灰。

**工具级**就是工具详情里那个与 JSON / 定义并列的页签（Postman 的 Params / Headers 也是这么排的），
用同一套表单，但**没有弹窗**——它本来就属于"当前选中的这个工具"，切工具跟着换一份即可。
它只作用于这个工具的调用，典型用途是工具专属的 trace id，或让不同工具走不同角色 / 额度：

```
│ JSON │ 请求头 (2) │ 定义        │ 历史 (3) │
│ ┌────────────────────────────────────────┐ │
│ │ [X-Trace-Id   ▾][abc123            ] × │ │
│ │ [Authorization▾][Bearer •••••••••• ] × │ │
│ └────────────────────────────────────────┘ │
│ [添加一行]                □ 显示敏感值     │
│ 已生效 · 2 项，只作用于本工具的调用        │
```

**没选中工具时这一页不出现**（工具级头按工具存，没有工具就没有可编辑的对象），stdio 服务器上同理。
反过来，建连时还不知道要调哪个工具，所以**工具级头不会出现在 `initialize` 与 SSE 的 GET 长连接上**——
这一句也写在页签的悬停提示里。

两级的**写入时机不同**：服务器级点「确定」才写入，工具级每敲一下就写。但都**不用重连**（http 每次请求都重新读这份配置；sse 长连接上带的是建连当时的头，
重连后才会换新值）。两份数据都写在服务器配置本身里，所以导出配置、编辑服务器都不会把它们丢掉——
「编辑服务器」对话框里因此不再重复提供入口。导出时工具级头写成扩展字段
`_mcpDebugger.toolHeaders`，标准字段（`command` / `url` / `headers`）保持干净，
别的客户端拿这份 JSON 照样能连，只是看不到工具级头。

**「历史」页签把每次调用记成一张卡片，卡片上只有一行。**调试 MCP 工具时，
重复动作几乎总是"把上一次那份原样再发一次"或"在上次的基础上改一个值"，而不是从零填一遍：

```
│ JSON │ 请求头 (1) │ 定义        │ 历史 (3) │
│ ╭────────────────────────────────────────╮ │
│ │▍● 成功            10:23:45   128 ms    │ │
│ │▍                      [ 重新调用 ]     │ │
│ ╰────────────────────────────────────────╯ │
│ ╭────────────────────────────────────────╮ │
│ │▍● 工具报错         10:19:52    86 ms   │ │
│ │▍                      [ 重新调用 ]     │ │
│ ╰────────────────────────────────────────╯ │
│ 共 3 条记录 · 悬停看详情                   │
```

- **卡片只留一行**：左边是**状态词**（配状态圆点），右边是**时刻**与**耗时**两列，都右对齐。
  入参与响应**不印在卡片上**——窄边栏里它们只会被吃掉一半，而"哪次通了、哪次卡住"
  靠状态 + 时刻 + 耗时这三样就够了。左侧那条色条分红 / 黄 / 绿三色；**状态词本身不染色**，
  选中时压在选中背景上照样读得清。
- **入参与响应全在悬停气泡里**：完整入参（原样展开，最多 12 行）、响应预览、失败原因都在那儿。
  代价是**两条入参、状态、耗时都一样的记录，在列表里长得一模一样**——要分清就悬停一下。
  这是显式选择：卡片能被一眼扫过去，比"不用悬停也能分辨"更值钱。
- **「重新调用」按钮**：用这条记录的入参**立刻再发一次**，同时把它摆回「JSON」页签，
  结果照常落在结果区。它是真发请求——带副作用的工具（写文件、下单、发消息）点下去就会执行，
  没有确认环节。不能调用时（没选中工具 / 上一次还没回来）按钮画成禁用态，悬停会说明原因。
- **点条目仍然是"只带入"**（「带入参数」按钮效果相同）：内容写回「JSON」页签并**自动切过去**——
  停在历史页上只会看到列表"一点没变"，容易以为点空了。覆盖掉的内容可以 `Ctrl+Z` 撤销。
- **成功、服务端报错（`isError`）、本地失败都记**：失败那一次的入参往往才是要复用的那一份。
- 耗时**不到 1 秒给毫秒、超过给秒**（`2413 ms` 要心算一下才知道是两秒多）。
- **响应也记下来了**：同一份入参、结果完全可能不同（上次超时、这次通了），只看入参是分辨不出来的。
  响应只存开头 240 字符的**预览**，不是完整结果——完整结果始终在结果区里。
  1.0.5 之前存下的老记录没有这一项，悬停时那一段显示 `—`。
- 记录按 `serverId + 工具名` 归类，默认保留**每个工具最近 20 条**（全局上限 400 条），
  存在 IDE 配置目录的 `mcp-debugger-history.xml` 里，与服务器配置分开存放——
  清空历史不会碰到你的服务器配置。删除服务器时，它的历史会一起清掉。
- 连续用**同一份入参**调同一个工具不会堆出一屏重复：只把最上面那条刷新成这次的时刻与结果。


**窗口窄了会自动换排法。** 宽度小于 520px（右侧边栏的常态）时，「目录树 / 详情」从左右并排
改成上下堆叠——并排至少需要"目录 180px + 详情 300px"，窄边栏里那样只会把目录挤成一条缝。
把工具窗口拖宽到 520px 以上会自动变回左右分栏。

**三条分隔线都能拖**（目录/详情、详情/日志，以及详情区内部的参数/结果）：鼠标移到分隔线上
光标会变成调整形状，拖就行。日志区除了拖，还能用工具栏的 **▤** 开关或日志标题栏左侧的
**▼** 折叠/展开——折叠状态会被记住。

## 工程结构

```
src/main/java/com/tool4j/mcp/
├── model/          # 纯数据模型
│   ├── McpServerConfig.java    # 一份服务端配置（传输、命令/地址、环境变量、headers、toolHeaders）
│   ├── ToolHeaders.java        # 工具级请求头（toolName + 一组键值对）
│   ├── McpServerInfo.java      # initialize 的返回：协议版本 + 能力
│   ├── McpTool.java            # 工具：name / title / description / inputSchema
│   ├── McpResource.java        # 资源与资源模板
│   ├── McpPrompt.java          # 提示词及其参数
│   ├── McpCallResult.java      # 统一结果载体（归一化 content/contents/messages 三种形态）
│   ├── ToolCallRecord.java     # 一次调用的历史记录（入参 + 响应预览 + 结局 / 耗时），XmlSerializer 友好的纯字段 POJO
│   ├── TransportType.java      # STDIO / HTTP / SSE
│   └── KeyValue.java           # 键值对（env / headers）
│
├── protocol/       # 协议层，不依赖任何 IDE 类 → 可单独测试
│   ├── JsonRpc.java            # JSON-RPC 2.0 信封的构造与拆解
│   ├── JsonUtil.java           # Gson 的薄封装（取值、建对象、错误描述）
│   ├── McpClient.java          # 会话主类：握手、tools/list 翻页、tools/call、反向请求应答
│   ├── McpConfigParser.java    # 解析 mcpServers JSON
│   ├── SchemaUtil.java         # JSON Schema 解析：$ref / allOf / enum / default / required
│   └── McpException.java       # 带 JSON-RPC error 详情与 data 的异常
│
├── transport/      # 三种传输，统一 McpTransport 接口
│   ├── McpTransport.java       # 接口：send / listen / close
│   ├── AbstractTransport.java  # 公共：ID 生成、待响应表、监听器派发
│   ├── StdioTransport.java     # 子进程 stdio
│   ├── HttpTransport.java      # Streamable HTTP
│   ├── SseTransport.java       # 旧版 HTTP+SSE
│   └── Transports.java         # 工厂
│
├── service/
│   └── McpProjectService.java  # Project 级 Service：持会话 + 每个会话最后拉到的目录快照
│
├── settings/
│   ├── McpSettings.java        # @State 持久化 + 变更广播（MessageBus Topic）
│   └── McpCallHistory.java     # 工具调用历史：独立 @State / 独立 xml，带上限裁剪与广播
│
├── util/
│   ├── McpConfigFiles.java     # 扫描工程内常见 MCP 配置文件位置
│   ├── Os.java                 # 路径与命令的平台差异
│   └── PluginInfo.java
│
└── ui/
    ├── McpToolWindowFactory.java  # 工具窗口入口
    ├── McpPanel.java              # 主面板：工具栏 + 目录树 + 详情区 + 日志
    ├── ImportConfigDialog.java    # 从文件 / 粘贴导入配置
    ├── ServerEditDialog.java      # 新建 / 编辑服务端（按传输切换表单，请求头不在这里）
    ├── ServerHeadersDialog.java   # 服务器级请求头弹窗（工具栏「请求头 · N」的落地页）
    ├── HeadersFormPanel.java      # 请求头表单（两级共用）：键可下拉选常用头、值可按需打码
    ├── RequestHeadersPanel.java   # 工具级「请求头」页签（仅 http / sse）→ McpServerConfig.toolHeaders
    ├── CallHistoryPanel.java      # 「历史」页签：卡片式列表（一行状态+时刻+耗时 + 自绘「重新调用」按钮），悬停给详情
    ├── ToolDetailPanel.java       # 工具详情：JSON / 请求头 / 定义 / 历史 四个页签 + 调用入口
    ├── ResourceDetailPanel.java   # 资源 / 资源模板读取
    ├── PromptDetailPanel.java     # 提示词渲染
    ├── SchemaFormPanel.java       # JSON Schema → 表单（当前未接入界面，见文件头说明）
    ├── ResultView.java            # 调用结果：直接显示 JSON + 复制原文
    ├── LogConsole.java            # 报文日志
    ├── KeyValueTable.java         # 键值表格控件（当前用于 env）
    ├── Editors.java / Ui.java / Bg.java  # 编辑器、主题色、后台任务的小工具
```

**设计约定**

- 只依赖 `com.intellij.modules.platform` 基础模块 → 同一个包能装进所有 JetBrains IDE。
- 唯一的第三方依赖是 **Gson**（MCP 是 JSON-RPC over JSON，足够）。
  *不*引入官方 Java MCP SDK——它带 reactor / slf4j，在插件类加载器里容易和平台自带版本打架。
- 协议层（`protocol` / `transport` / `model`）不引用任何 IDE 类，可以直接用 JUnit 测。
- 所有网络/子进程调用都在 `Task.Backgroundable` 里跑，绝不在 EDT 上阻塞。

## 端到端冒烟测试

`smoke/` 下放着两套可在命令行直接跑的冒烟测试，配套两个**最小 MCP 服务端**（纯 Python 标准库，无依赖）：

| 文件 | 作用 |
| --- | --- |
| `smoke/mini_mcp_server.py` | 最小 stdio 服务端：echo / add / screenshot（返 base64 图）/ boom（返错误）+ 资源 + 提示词 + 反向 `roots/list` |
| `smoke/mini_mcp_http.py` | 最小 HTTP 服务端：`/mcp` Streamable + `/sse` 旧版 |
| `smoke/SmokeMain.java` | stdio 全链路，**37 项断言** |
| `smoke/SmokeHttp.java` | Streamable HTTP + 旧版 SSE + 会话可恢复性 + 报错可读性，**21 项断言** |
| `smoke/dump_server.py` | 排障用：把收到的原始 HTTP 报文逐字节打出来（看客户端到底发了什么头/体） |
| `smoke/run.sh` | 一键跑（自动找 JDK / Python / gson，编译并执行） |

一条命令跑全部：

```bash
./gradlew classes    # 先编主代码
./smoke/run.sh       # stdio + Streamable HTTP + 旧版 SSE
./smoke/run.sh stdio # 只跑 stdio
./smoke/run.sh http  # 只跑两种 HTTP 传输
```

`run.sh` 会自动探测 JDK（依次看 `MCP_SMOKE_JAVA`、`JAVA_HOME`、`PATH`）、Python
（`MCP_SMOKE_PYTHON` 或 `PATH` 上的 `python3`/`python`）以及 gson jar（先从构建沙箱里找，
再从 Gradle 缓存找）。需要覆盖时用环境变量：

```bash
MCP_SMOKE_JAVA=/path/to/jdk-17 \
MCP_SMOKE_PYTHON=/path/to/python3 \
MCP_SMOKE_PORT=8931 \
./smoke/run.sh
```

覆盖点包括：握手与协议版本协商、`tools/list` 游标翻页、`tools/call` 成功与错误、
`resources/list` + `resources/read`、`prompts/list` + `prompts/get`、反向 `roots/list` 应答、
子进程 stderr 转发、非 ASCII 内容（中文往返）、会话复用与关闭、**关闭后能重建会话**、**连不上时报错可读**。

> 最近一次全量运行：**stdio 37/37 通过，HTTP 21/21 通过**。

> 两个 fixture 都**显式把 stdio 钉成 UTF-8**。MCP 规定 stdio 传输一律 UTF-8，而 Windows 上
> Python 面向管道时默认取系统 ANSI 代码页（cp936），不钉住的话中文会以 GBK 字节发出去，
> 客户端按 UTF-8 解就是乱码——而且这个默认值随宿主 locale 漂移，会让测试时绿时红。

> `mini_mcp_http.py` 还会**主动拒绝 h2c Upgrade 协商**（回 400 `Parse error`），
> 如实模仿 uvicorn 的行为。这是为了让冒烟测试守住"HTTP 传输必须钉死 HTTP/1.1"这条线——
> 见下方"已知坑"。

## FAQ

**Q：为什么不做成 PyCharm 专用插件？**
A：因为没必要。只依赖平台基础模块，一份包同时适用 PyCharm / IDEA / WebStorm / GoLand，
维护成本反而更低。

**Q：能用 PyCharm 社区版吗？**
A：可以。`stdio` 与 `HTTP`/`SSE` 都是纯 JDK 能力，社区版完全够用。

**Q：调用报 `Method not found`？**
A：不同 MCP 服务端实现的能力差异较大。先在 Console 里看 `initialize` 返回的 `capabilities`，
确认它声明了 `tools` / `resources` / `prompts` 中的哪几项。

**Q：stdio 服务端起不来？**
A：多半是命令不在 IDE 的 PATH 里（`npx` / `uvx` 最常见）。在配置里写绝对路径，
或把 `env` 里的 `PATH` 显式补全。子进程的报错会原样出现在 Console 面板。

**Q：连 Python 写的 MCP 服务端（FastMCP / uvicorn）报 `HTTP 400 Parse error`？**
A：已经处理掉了，不用管——但值得知道原因。JDK 的 `HttpClient` 默认走 HTTP/2，
明文 http 下会先发一轮 **h2c Upgrade 协商**（`Connection: Upgrade, HTTP2-Settings`
加 `Upgrade: h2c`）。curl 和 Python 的 `http.server` 会忽略这组头，所以用 curl 试是通的；
但 **uvicorn（httptools/h11）不实现 h2c**，解析不了就把请求体当成空的交给上层，
于是服务端报 `Parse error: Expecting value: line 1 column 1`。
插件的 HTTP / SSE 传输因此**都钉死了 HTTP/1.1**。MCP 报文很小，用不上 HTTP/2。

**Q：第一次连接失败之后，再点"连接"就没反应了（日志只有一句"连接失败：连接已关闭"）？**
A：这是 1.0.0 的一个已修 bug。握手失败时会话会自己关闭，而旧实现把已关闭的实例
继续缓存在服务里还回去，导致后续重试不做任何网络请求就直接失败。
现在缓存发现实例已关闭会就地重建。若你用的是旧包，改一下服务器配置（或重启 IDE）
就能绕开。

**Q：能存敏感 token 吗？**
A：可以，但配置本身以明文存在 IDE 配置目录，不要直接提交带密钥的工程级配置。
token 在工具栏第一行的「请求头 · N」按钮里改（弹窗里选 `Authorization`，值填 `Bearer xxx`），
点「确定」后立刻生效、不用重连。名字里含 token / key / secret 的值可以取消勾选「显示敏感值」打码。

**Q：带鉴权的 http 服务端，第一次怎么连？**
A：先保存服务器（鉴权项没填、这次连接会失败是正常的），然后点工具栏第一行、服务端下拉框旁边的
「请求头 · N」把 token 填好，再点「连接」。这个入口刻意**不受连接状态影响**——没连上时照样能编辑，
就是为了这一步。填完可以直接在弹窗里点「测试连接」，它拿表单里这份还没保存的头去试一次握手，
通过再点「确定」。

**Q：请求头为什么要放在工具窗口里，而不是「编辑服务器」对话框里？**
A：token 是会跟着调试反复过期、反复换的东西，值得放在手边；配置对话框里的东西是"部署期"的，
每次改都要走"管理 → 编辑 → 保存 → 重连"。不过它现在是个弹窗（此前是详情区的一张常驻卡片）：
服务器级这一层和"当前选中哪个工具"没有关系，摆在详情区总让人以为它属于某个条目；
代价是改一个字不能再即时生效，改成点「确定」才写入——反正它通常就一个 token。

**Q：服务器级和工具级的请求头有什么区别？**
A：服务器级带在**所有**请求上（含 `initialize` 握手与 SSE 建连），工具级只带在那个工具的
`tools/call` 上，同名键覆盖服务器级。除了鉴权，工具级还能表达"某个工具额外带一个 trace id"、
"不同工具走不同角色 / 额度"这类服务器级表达不了的细分。

**Q：SSE 连一会儿就断，工具列表也跟着没了，重新连接还必定先失败一次？**
A：那是 1.0.4 及以前三个缺陷叠出来的，1.0.5 已修。根因分别是：传输层拿"拿到过 endpoint"当存活判据
（长连接断了它仍认为自己活着）、会话层只看"有没有 `close()` 过"（于是把死实例原样还回来，
一个请求都不发就秒失败）、`sse` 的 `start()` 又不可重入（重连会拿着上一个会话的 endpoint 去发
`initialize`，服务端当孤儿丢掉就是干等超时）。现在：长连接断开立刻可见、死会话就地重建、
`start()` 可重入；**工具列表不再因为断线而消失**（目录快照存在会话服务里，断线只把它标成"已断开"），
并且后台按 1s → 2s → 4s → 8s → 16s → 30s 退避**自动重连**，连败 6 次停下等你手点。

**Q：调过一遍的参数，下次还要重新填吗？**
A：不用。每次调用都在「历史」页签里留一张卡片（成功、报错、失败都记），卡片上一行写清
**状态、时刻、耗时**，入参与响应在悬停气泡里；点条目填回 JSON 页签，点「重新调用」直接重发。
记录落在 IDE 配置目录的 `mcp-debugger-history.xml`，重启 IDE 也还在；每个工具保留最近 20 条。
它和服务器配置分开存，所以「清空」历史不会动到你的服务器列表。

**Q：历史里为什么没有资源 / 提示词？**
A：它们没有入参 JSON（资源读的是一个 URI），记下来也无从"一键带入"，混进来只会让列表不一致。
真正的报文级留痕在底部 Console 里，那一条是全量的。

## 版本历史

### 1.0.5

**新增：请求头分两级（服务器级 / 工具级），两级都改成表单填写。**

- **服务器级**请求头的入口在工具栏第一行、与服务端下拉框同排（`请求头 · N`），点开是一个弹窗：
  一行一个头，键可以从下拉里挑常用项（Authorization / Content-Type / Accept / X-Trace-Id …），
  选中 Authorization 会自动带上 `Bearer `。它带在**所有**请求上，含 `initialize` 握手与 SSE 建连。
  入口刻意不受连接状态影响——带鉴权的新服务器恰恰是在"还没连上、树是空的"这一刻需要填 token。
  弹窗里还带**测试连接**：拿表单里未保存的头试一次握手，通过再点「确定」。
- **工具级**请求头是新增能力：工具详情的「请求头」页签，只作用于这个工具的 `tools/call`，
  与服务器级**逐键合并、同名以工具级为准**。典型用途是工具专属的 trace id，或让不同工具走不同角色。
  建连时还不知道要调哪个工具，所以它不会出现在 `initialize` 与 SSE 的 GET 长连接上。
- **不再手写 JSON。** 两级原先都是 `{"Authorization": "Bearer …"}` 这样的编辑区，敲错一个引号整块
  不生效、还得先记住头名；现在共用一套表单（`HeadersFormPanel`），空键的行直接滤掉，
  不存在"改到一半把能用的值覆盖掉"。名字含 token / key / secret 的值可取消勾选「显示敏感值」打码。
- 两级的写入时机不同：**服务器级点「确定」才写入**（它通常就一个 token，边改边写意味着手一滑就
  把能连上的那个值盖了），**工具级每敲一下就写**（它是随调试反复改的东西，多一道确认只会碍事）。
- 导出配置时工具级头写成扩展字段 `_mcpDebugger.toolHeaders`，标准字段（`command` / `url` / `headers`）
  保持干净——别的客户端拿这份 JSON 照样能连，只是看不到这一层。导入时能读到就读。
- 「编辑服务器」对话框照旧不提供第二个入口，但保存时会把两级请求头**原样带过去**
  （该路径是整份覆盖语义，漏一处就是"点一次保存把 token 抹掉"）。

**新增：请求头表单的输入框加高。**

- 请求头表单那两处（服务器级弹窗 / 工具级页签）的输入框高度从 22px 提到 **28px**。
  参数表单那边一行十来个控件、高度得省着用；请求头这里一行只有"键 + 值"两个，
  而键列还要占掉一截宽度，值框常常只剩一两百像素——高度给足一点，才像个"能填长 token 的地方"。
  两处的取舍不同，所以刻意没有把两者拉回同一个值。

**新增：「历史」页签改成卡片式列表。**

- 一条记录一张卡片，卡片上**只有一行**：左边是**状态**（配状态圆点），右边是**时刻**与
  **耗时**两列、都右对齐；入参与响应一律不印在卡片上，交给悬停气泡。
- 卡片带圆角与主题边框色，左侧一条色条按结局着色（绿 / 黄 / 红）。
  状态词本身**不染色**——早先是把文字也染成状态色，选中时深红压在蓝色选中底上根本读不出来；
  现在文字只分"正常前景色 / 弱化的灰"两档，选中时整卡切到选中前景色。
- **卡片底部有「重新调用」按钮**：用这条记录的入参立刻再发一次，同时把它摆回「JSON」页签。
  它是真发请求，带副作用的工具点下去就会执行。不能调用时按钮画成禁用态，悬停说明原因。
- 悬停气泡里是完整入参（原样展开，最多 12 行）+ 响应预览 + 失败原因，
  也是分辨两条"看起来一样"的记录唯一的出口。
- 耗时**不到 1 秒给毫秒、超过给秒**（`2413 ms` 要心算一下才知道是两秒多）。
- **响应现在也会记下来**（只存开头 240 字符的预览，不是完整结果）：
  同一份入参、结果完全可能不同（上次超时、这次通了），只看入参是分辨不出来的。
  同一份入参连着重发时，除了时刻与结局，**响应预览也一起刷新**——
  否则会出现"状态写着失败、预览却还留着上次成功内容"的自相矛盾。
- 1.0.5 之前存下的老记录没有这一项，悬停气泡里那一段显示 `—`。

**修复：SSE 断连后重连必定先失败一次、工具列表跟着清空。**

- 传输层加"长连接读线程还活着"的判据，`isAlive()` 不再拿"拿到过 endpoint"当准——
  长连接被服务端 / 反向代理 / 本地代理掐掉后 endpoint 字段还在，旧判据会坚称连接还活着。
- 会话层改用"可用性"判据（`close()` 过、或连上过但传输已死，都算不可复用并就地重建），
  不再把死实例原样还给上层。
- `sse` 的 `start()` 改成**可重入**：先拆干净上一次的长连接与 endpoint，再重建等待闩、
  复位一次性标志位；并用"连接代次"保证被替换掉的旧读线程不会把主动重连误报成断线。

**新增：断线不再让工具列表消失，并自动重连。**

- 每个会话最后拉到的目录（工具 / 资源 / 模板 / 提示词）由会话服务留一份快照，断线时树照常显示，
  只在摘要里标"已断开"——那些条目只是暂时不能调用。会话被重建后同样从快照渲染，不会闪成空白。
- 被动断开后按 **1s → 2s → 4s → 8s → 16s → 30s** 退避自动重连，连败 6 次停下并在状态栏 / 日志里
  说明。用户手动点「连接 / 断开」或切换服务器时，排队中的重连立即取消。

   改用平台指定的 `getChildActionsOrStubs()`——它不传事件、不求值，2023.3.8 起就有。
2. **有几处文字切了语言不跟着变**：
   - **「JSON」「定义」两个页签标题**——加进页签的是 `wrapEditor()` 包出来的容器，
     换标题时却拿里面的编辑器去 `indexOfComponent` 找，永远返回 `-1`，
     `setTitleAt` 静默不执行。改用容器本身去找（「历史」是直接加进去的，没有这个问题）。
   - **服务器编辑对话框的「取消」**：只设了 `setOKButtonText`，取消键由平台按 *IDE 的语言*
     渲染，于是插件切英文后按钮条变成「Save / 取消」。
   - **确认框的「是 / 否 / 确定」**：`Messages.showYesNoDialog` / `showInfoMessage` 的按钮
     同样跟 IDE 语言走。改用 `Messages.showDialog(..., options, ...)` 自己给按钮文案。

### 1.0.3

**新增：「历史」页签**——工具详情区第四个页签，记下每次调用**真正发出去的那份入参**。

- 成功、服务端报错（`isError`）、本地/协议层失败**三种结局都记**：失败那次的入参往往才是要复用的那份。
- 点条目即填回「JSON」页签**并自动切到该页签**——代入后 `Ctrl+Enter` 直接重发；
  覆盖掉的内容可 `Ctrl+Z` 撤销，动作栏那行提示会写明（提示放在页签外，因为提示的时候历史页已经切走了）。
- 列表两行一条：上行「时刻 + 结局 + 耗时」（圆点按结局着色），下行 `path=src/main · depth=2` 摘要；
  完整入参与失败原因在悬停提示里。附带带入 / 复制 / 删除 / 清空。
- **连续用同一份入参调同一个工具不新增条目**，只刷新最上面那条的时刻与结果——否则重试会堆出一屏重复。
- 按 `serverId + 工具名` 归类，每工具 20 条、全局 400 条；独立存 `mcp-debugger-history.xml`，
  与服务器配置分开（清空历史不动配置），删除服务器时连带清理它的历史。
- 升级无需迁移：首次运行自动生成该文件，1.0.2 及以前的配置原样可用。

**修复**

1. **历史列表点开一片空白**（标题已显示 `历史 (2)`）：列表渲染器把两个文字标签造出来量了尺寸、
   却**从未 add 进行面板**，于是每行高度正确、内容是空的，且不报任何错。

   就会留下一份仍在收消息总线的旧实例（连结果区定时器一起漏），每重开一次漏一份。
